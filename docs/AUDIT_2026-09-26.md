# Audit against the proposal — 2026-09-26

Proposal audited: `docs/proposal.docx` (byte-identical to *Proposal V2 — Reason Or
Recall 22-9-26.docx*). Evidence: the code at commit `3c375f2` + this audit's
changes, and the Kaggle runs in `Results/` (25-9-26 2000Hrs, 25-9-26 2030Hrs,
26-9-26 1500Hrs).

Legend: **Done** = implemented and run on Kaggle · **Built** = implemented and
tested locally, never run for real · **Partial** · **Not started** ·
**Drift** = differs from what the proposal says.

---

## 1. Where we are in one paragraph

The **infrastructure** of Phase 1 is done and proven on Kaggle's T4: data for all
three benchmarks, 4-bit QLoRA training, generation, scoring, logging, the
never-repeat registry, pause/resume, and (as of today) a figure report. The
**first end-to-end experiment** completed on 2026-09-26: the smoke run (A5,
Qwen2.5-3B, 64 training questions, 32 test questions, 5.5 min) scored **0.0%**
exact match. That number is expected to be low after 4 training steps, but the
report shows it also exposes an unsettled **answer-matching rule**: the same
answers score up to 15.6% under more lenient rules. **The science has not
started**: no study run, and none of the three things that make the paper novel
exist yet: the **clean set** (§5.3), the **~32B baseline/teacher** (Job 3), and the
**reason-vs-recall** measures beyond the basic program check (§5.5, §7).
Measured training speed (310 tokens/s) puts the configured sweep at **~880
GPU-hours** against the proposal's **120–180**: the plan must be cut or
restructured before the sweep.

### 5.3 Contamination-controlled set (the key artifact)
| Proposal says | Status |
|---|---|
| SEC EDGAR filings dated after every model's cutoff | **Not started** |
| Parse tables + text programmatically | **Not started** |
| Deterministic templates (percentage change, ratio, sum/difference) | **Not started** |
| Keep only items whose gold program executes | **Built** (the verification gate in `scripts/build_clean_set.py` is wired) |
| ~150–400 items; manual spot-check of a sample (§7) | **Not started** |

This is the linchpin of the paper and has zero implementation. Every
`clean`-split experiment is currently skipped as "not ready" (no attempts used).
Two design points to settle before building it:
1. **Cutoff boundary.** Phase-1 models' latest cutoff proxy is 2024-09-19; a
   Phase-2 frontier API model may have a 2025–2026 cutoff. Choose filings from a
   window that is after **all** models that will ever be scored on the set, e.g.
   FY2025 10-Ks filed Jan–Mar 2026, and record the rule.
2. **Question-style confound (validity threat, not in the proposal).** Clean
   questions are template-generated; FinQA's are human-written. A standard→clean
   drop then mixes *contamination* with *question style*. Recommended control:
   run the same templates on **pre-cutoff** filings (e.g. FinQA's own source
   10-Ks) to get a "templated-standard" set. Gap = templated-standard −
   templated-clean isolates recency/contamination.

## 4. Decisions needed (in order)

1. **Answer-matching rule (before any real result).** The proposal says "Exact
   Match" but not how numbers are matched. Current rule: within 0.001 absolute
   for answers under 1, and "14.5%" read as 14.5 (FinQA gold is 0.145). Program
   arms compute exactly and barely notice. Answer-only arms (A1–A6) are hit
   hardest, which would **inflate PoT's advantage (H4) by construction**.
   Options, applied identically to every arm:
   - (a) strict (current);
   - (b) accept a percent-form answer as the decimal, within 1% relative;
   - (c) match FinQA's human-written answer at the precision the annotator
     wrote it (often whole percents: gold 0.14464 is written "14%").

   Recommendation: primary = (b), with (a) reported alongside. Do **not**
   evaluate arithmetic written in the answer ("301/2575"): that would hand
   answer-only arms a calculator, which is exactly what separates them from PoT.
   Whatever is chosen: fix it before the first study run and state it in the paper.
2. **Compute plan.** Pick a row of the table in §3, or amend the proposal's
   120–180 h. This sets `epochs`/seeds/models in `configs/`, which are part of
   every experiment's id, so it must be decided before the first study run.
3. **Early stopping (proposal §5.4).** Implement it (dev accuracy on 200 dev
   items after each epoch, ~4 min for answer-only, keep the best checkpoint) or
   amend the proposal to "fixed epochs, dev loss monitored".
4. **Clean-set design.** Filing window (§5.3 point 1) and whether to add the
   templated-standard control (§5.3 point 2).
5. **CoT rationale source for A6.** Neither the proposal nor the code says where
   the natural-language rationales come from. Options: templated from the gold
   program (cheap, deterministic, but not natural) or generated by the 32B
   teacher and kept only if its final answer is right (natural, costs teacher
   hours).
6. **Membership-inference / verbatim check.** Add it to the plan: it is a
   stated mitigation (§7), and RQ3 needs its per-item "likely seen" label.
7. **Dollar convention** for the per-dollar frontier on free hardware.

## 5. Recommended order of work

1. Settle decisions 1–3 (no GPU time needed).
2. **Start the clean set now**: it is on the critical path, needs no GPU, and
   everything novel depends on it.
3. First study run: A5 Qwen2.5-3B, full FinQA, with the chosen epochs (about 6 h
   per epoch; pauses and resumes across sessions automatically).
4. A7 (PoT gold) on 3B; add the grounding check to faithfulness.
5. Check whether arXiv:2408.12337 released traces; then `load_teacher` (32B on
   T4×2) for A3/A4 and, if needed, A8 traces.
6. A1/A2 (few-shot) and the post-hoc proxy; membership-inference check.
7. Scale to 7B/8B within the chosen compute plan.
